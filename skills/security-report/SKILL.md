# 安全报告生成 Skill

## 适用场景

当用户要求“生成报告”“整理成报告”“形成交付文档”“写安全报告”“输出整改/处置总结”时使用本 Skill。

## 工作方式

1. 先识别用户已经提供的事实材料，包括告警、日志、资产、影响范围、处置动作、分类结果、风险说明和待确认事项。
2. 不补造没有证据支持的细节。缺失信息必须标注为“待补充”或“待确认”。
3. 如果只有零散材料，先输出可直接复制到报告里的结构化草稿，而不是要求用户重新提问。
4. 如果用户要求正式交付口径，语气应克制、准确、面向项目交付。

## 输出格式

默认输出以下结构：

1. 报告标题
2. 一、事件/任务概述
3. 二、输入材料与证据来源
4. 三、关键发现
5. 四、影响范围
6. 五、处置与整改建议
7. 六、待确认事项
8. 七、结论

## 边界

- 不声称已经生成 Word、PDF 或其他文件，除非工作台实际完成了文件导出。
- 不声称已经调用设备、平台、MCP、脚本或互联网查询。
- 不编造客户名称、IP、漏洞编号、时间线或处置结果。
